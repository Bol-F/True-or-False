# RuFact

Полированный MVP для вероятностной проверки русскоязычных текстов на признаки недостоверной информации. В репозитории есть обученный и измеренный ML-бэкенд, FastAPI API и Next.js интерфейс.

## Полный локальный запуск

Нужны Node.js, Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
npm install
uv sync --project ml
copy .env.example .env.local
```

Перед первым запуском заполните `ML_API_JWT_SECRET` в `.env.local` случайной
строкой длиной не менее 32 байт. Один и тот же секрет используется Next.js и
FastAPI; браузеру он не передаётся. Для production создайте отдельный секрет.

Запустите два процесса в отдельных терминалах:

```bash
npm run dev:ml
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). FastAPI документация доступна на [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Если `ML_API_URL` не задан, Next.js route явно использует помеченный `demo-heuristic`. Если URL задан, ошибка ML-сервиса показывается пользователю — скрытой подмены ответа демо-результатом нет.

## Проверки

```bash
npm run typecheck
npm run lint
npm run build
npm run check:gemini
npm run test:gemini
npm run test:report
npm run test:security
npm run test:e2e
npm run lint:ml
npm run test:ml
```

`npm run check` выполняет все статические проверки, unit-тесты, production build и тесты ML. Playwright e2e запускается отдельно, потому что ему нужен установленный Chromium. CI выполняет оба этапа автоматически.

Клиентская интеграция анализа изолирована в `lib/api.ts` и всегда обращается к same-origin `POST /api/analyze`. Next.js route проксирует серверный `ML_API_URL`, поэтому адрес FastAPI не попадает в браузерный bundle. Каждый запрос Next.js к `/predict` подписан короткоживущим JWT, связанным с точным телом запроса и request ID.

## Безопасность и ограничение нагрузки

Публичный `POST /api/analyze` ограничен по умолчанию десятью запросами в минуту
на хешированный адрес клиента. В development используется локальный счётчик. В
production приложение требует общий Upstash Redis, поэтому лимит действует сразу
на всех serverless-инстансах; при неправильной конфигурации route закрывается с
`503`, а не остаётся без защиты. При превышении лимита возвращаются `429`,
`Retry-After` и стандартные заголовки лимита.

FastAPI принимает вычислительно дорогой `/predict` только с валидным HS256 JWT,
ограничивает параллельные предсказания, проверяет размер тела и в production
скрывает OpenAPI. Next.js добавляет CSP, HSTS, защиту от clickjacking, MIME-sniffing
и опасных browser permissions. Полная модель угроз, остаточные риски и аудит N+1
описаны в [`docs/SECURITY.md`](docs/SECURITY.md).

## Опциональное второе мнение Gemini

Gemini подключён только как экспериментальное второе мнение. Он не меняет класс и калиброванную уверенность основной ML-модели, а его собственная уверенность показывается только качественно. Если Gemini не отвечает, превышает квоту или возвращает некорректный ответ, RuFact всё равно возвращает основной ML-результат.

После создания **нового** ключа задайте только серверные переменные в `.env.local`:

```dotenv
GEMINI_REVIEW_ENABLED=true
GEMINI_API_KEY=replace-with-a-fresh-key
GEMINI_MODEL=gemini-3.5-flash-lite
```

Ключ нельзя называть `NEXT_PUBLIC_*`, помещать в клиентский код или коммитить. В интерфейсе отправка в Gemini выключена по умолчанию и требует отдельного согласия для текущего текста. История не хранит ответ Gemini и не вызывает его повторно.

Текущий бесплатный режим анализирует только переданный текст и не использует Google Search grounding. По [условиям Gemini API](https://ai.google.dev/gemini-api/terms) данные бесплатного тарифа могут использоваться Google для улучшения продуктов и обрабатываться людьми, поэтому нельзя отправлять личные, конфиденциальные или чувствительные данные. Общий serverless-safe rate limit защищает и основной анализ, и расходуемый вызов Gemini.

`npm run check:gemini` выполняет один реальный запрос с фиксированным нечувствительным текстом и выводит только безопасную сводку без ключа и полного ответа. Команда расходует квоту. `npm run test:gemini` проверяет запрос, строгий JSON-ответ, таймаут, блокировку и квоту через подставной `fetch`; реальный ключ и квота в тестах не используются.

Контракт поэлементного анализа описан в [`docs/CLAIM_ANALYSIS_CONTRACT.md`](docs/CLAIM_ANALYSIS_CONTRACT.md). Gemini возвращает только точные цитаты из исходного текста и консервативные категории без заявлений о внешней проверке.

После анализа результат можно скопировать, скачать как текстовый отчёт или передать через системное меню «Поделиться». Отчёт явно разделяет основной ML-результат, необязательное мнение Gemini и непроверенные утверждения. «Обратная связь» открывает локальную форму и подготавливает публичное GitHub Issue; исходный анализируемый текст туда автоматически не добавляется.

## Модель и accuracy

Модель `tfidf-word-char-logreg-ru-v2` объединяет словесные и символьные TF-IDF признаки, логистическую регрессию и отдельную sigmoid-калибровку. Обучающая выборка выросла с 2 039 до 3 707 текстов за счёт сбалансированной пары из 834 сатирических материалов Panorama и 834 новостей Lenta из Taiga. Версия KazFakeCorpus и оба архива Taiga зафиксированы и проверяются по SHA-256.

Главная оценка получена только из out-of-fold предсказаний на внешней русскоязычной выборке из 157 текстов:

- Accuracy: **80,89%** (bootstrap 95% CI: 74,52–86,62%)
- Macro F1: **80,88%**
- Precision FAKE: **84,93%**
- Recall FAKE: **76,54%**
- Confusion matrix `[[65, 11], [19, 62]]` для строк/столбцов `REAL, FAKE`

Внутренняя grouped CV accuracy 99,75% не используется как основная: она завышена из-за различий между официальными REAL и синтетическими FAKE текстами. Внешняя выборка тоже небольшая и связана с источниками, поэтому 80,89% — оценка на конкретном наборе, а не гарантия реального качества. Полный протокол, ограничения и воспроизведение описаны в `ml/MODEL_CARD.md`, `ml/README.md` и `ml/artifacts/metrics.json`.

Процент в карточке конкретного результата — калиброванная уверенность модели в этом ответе, а не общая accuracy.

Добавление Gemini само по себе не повышает измеренную accuracy. RuFact показывает оценку основной ML-модели 80,89% и не усредняет вероятности двух разных моделей.

## Переобучение

```bash
npm run train:ml
```

Команда загружает только зафиксированные версии датасетов, проверяет хэши, удаляет точные дубликаты с учётом лимита 5000 символов, повторяет оценку и записывает модель плюс манифест целостности в `ml/artifacts/`. Для распаковки RAR-архива Taiga нужен `bsdtar`/`libarchive-tools` (в Windows подходящий `tar` обычно уже установлен).

Локальная история проверок выключена по умолчанию и включается пользователем явно. Она хранит до 20 успешных проверок в `localStorage`, удаляет записи старше 30 дней и полностью очищается при отключении.

Инструкция по двухсервисному production-развёртыванию, переменным окружения, health-check и откату находится в [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).

Выполненные этапы 10-дневного MVP-плана собраны в [`docs/ROADMAP_10_DAYS.md`](docs/ROADMAP_10_DAYS.md).
